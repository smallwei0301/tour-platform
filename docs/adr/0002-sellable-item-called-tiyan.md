# 販售品項的類別詞是「體驗」，不是「行程」

平台庫存是異質的——從 90 分鐘的定點書法課到 11 小時的阿里山一日專車都是同一張 `activities` 表。「行程」蓋不住定點課程（「書法行程」不成句），midao2 UI 正是為了補這個洞而自創「服務」一詞，造成同一筆資料在主站叫「行程」（151 處）、在 midao2 叫「服務」（32 處）。

因此販售品項的類別詞統一為「**體驗**」：涵蓋全部庫存型態、是業界通用語（Airbnb／KKday 皆用），且貼合「賣的是人與體驗，不是套裝行程」的定位。「服務」一詞廢除。

## Consequences

- **「行程」不是全面禁用**，它保留唯一語意：`plan_itinerary`——**一個方案在當天的路線與時間安排**。「行程內容」「當日行程」仍是正確用法；「這個行程多少錢」則否（該說「這個體驗」）。
- 三層命名因此固定為：**體驗**（`activities`）→ **方案**（`activity_plans`）→ **行程**（`plan_itinerary`）。
- 同一個體驗在主站可直接預約、在接案頁走詢問，差別由 `midao_deal_mode` 表達，**不構成兩種不同的品項**。
- 需修改約 151 處主站文案與 32 處 midao2 文案；資料表與 API 欄位維持 `activities` / `activity_plans`（鐵律 1）。
